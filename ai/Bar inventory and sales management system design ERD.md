## Convex Data Model Fundamentals

Convex is a document database with relational capabilities. Key conventions that
apply throughout this document:

- Every document automatically receives `_id` (typed as `Id<"tableName">`) and
  `_creationTime` (a `number` epoch ms timestamp). These are **not declared** in
  the schema — Convex injects them automatically.
- Cross-table references use `v.id("tableName")` — Convex's typed foreign key.
  There are no JOIN statements; related documents are fetched via `ctx.db.get(id)`
  or parallel lookups using `Promise.all`.
- Indexes are declared with `.index("name", ["field1", "field2"])` chained on
  the table definition and queried with `.withIndex()` in query/mutation functions.
- There is no `INT`, `VARCHAR`, or `DECIMAL`. Types are `v.string()`,
  `v.number()`, `v.boolean()`, `v.id()`, `v.optional()`, `v.union()`,
  `v.literal()`, `v.array()`, and `v.object()`.
- Timestamps are stored as `number` (milliseconds since epoch via `Date.now()`).
  Human-readable calendar dates are stored as ISO 8601 strings (e.g. `"2026-03-22"`).
- There is no auto-increment primary key. The `_id` field is Convex's globally
  unique, system-generated document identifier.
- Referential integrity is enforced in mutation functions, not at the database level.

### 5. `userStockLogs`

Daily per-beverage stock sheet for a bar. The operating document is one per
`(barId, beverageId, logDate)` with `holder: "bar"`. `userId` is the waiter or
bartender the sale belongs to. `recordedByUserId` is the login that entered the
count, which may be an administrator. Older rows without `holder` were a
personal float and are not the book when a bar row exists. Stock updates from
`storeTransactions` apply to the bar's row for `txnDateKey` only — prior days
are never mutated.

> **v2.4:** The bar holds the stock. `barAssignments` links a user to a bar.
> Opening stock can be entered on the bar during setup. The next linked person
> continues from the bar's last finalized close.

| Field              | Convex Type            | Notes                                                        |
|--------------------|------------------------|--------------------------------------------------------------|
| `_id`              | `Id<"userStockLogs">`  | Auto-generated by Convex                                     |
| `_creationTime`    | `number`               | Auto-generated by Convex                                     |
| `shiftId`          | `v.id("shifts")`       | The waiter's F&B shift at this bar                          |
| `userId`           | `v.id("users")`        | Waiter or bartender the sale belongs to                      |
| `recordedByUserId` | `v.optional(v.id("users"))` | Login that entered the count. Optional on older rows. |
| `barId`            | `v.id("bars")`         | **[NEW]** Denormalized — direct bar reference                |
| `beverageId`       | `v.id("beverages")`    | Beverage being tracked                                       |
| `logDate`          | `v.string()`           | **[NEW]** ISO 8601 date this record covers, e.g. `"2026-03-26"` |
| `openingStock`     | `v.number()`           | Units carried over from previous day's `closingStock`        |
| `newStockReceived` | `v.number()`           | Cumulative qty issued via `storeTransactions` on this day    |
| `totalStock`       | `v.number()`           | `openingStock + newStockReceived` (persisted)                |
| `closingStock`     | `v.number()`           | Physical count at end of day                                 |
| `salesQuantity`    | `v.number()`           | `totalStock − closingStock − waste − comps` (persisted)  |
| `salesValue`       | `v.number()`           | `salesQuantity × unitPrice` (persisted)                      |
| `wasteQuantity`    | `v.optional(v.number())` | Spill / breakage excluded from sales                      |
| `compQuantity`     | `v.optional(v.number())` | Comps excluded from sales                                 |
| `unitCostAtSale`   | `v.optional(v.number())` | Snapshotted unit cost                                     |
| `cogsValue`        | `v.optional(v.number())` | Disappeared × unitCostAtSale                              |
| `isFinalized`      | `v.boolean()`          | **[NEW]** `true` after end-of-day reconciliation; blocks further updates |
| `lastUpdatedAt`    | `v.number()`           | **[NEW]** Epoch ms of last mutation (replaces `recordedAt`)  |

> Derived fields (`totalStock`, `salesQuantity`, `salesValue`) are stored rather
> than computed at query time to avoid expensive document fetches in Convex's
> query model.

**Stock Update Rule:** When an `"issue"` `storeTransactions` fires, the mutation
resolves the correct `userStockLogs` record using `(barId, beverageId, logDate)`
where `logDate` equals the transaction's `txnDateKey` (property-local date). It then increments
`newStockReceived` and recomputes `totalStock`. If no record exists for that date,
a new one is created with `openingStock` seeded from the bar's **last finalized**
closing stock for that beverage. The row's `userId` is still the salesperson
from `resolveBarSalesPerson` when a sale is saved, not the store clerk who issued
the stock.
If the record is already `isFinalized: true`, the mutation throws.
Edit and delete of an issue reverse those qty changes on the same day's log.

**Indexes:**

| Index Name                   | Fields                                   | Purpose                                                    |
|------------------------------|------------------------------------------|------------------------------------------------------------|
| `by_shiftId`                 | `[shiftId]`                              | All stock log entries for a shift (back-reference lookup)  |
| `by_userId_date`             | `[userId, logDate]`                      | All beverages for a user on a given day                    |
| `by_barId_date`              | `[barId, logDate]`                       | All beverages at a bar on a given day                      |
| `by_userId_barId_date`       | `[userId, barId, logDate]`               | All beverages for a user at a specific bar on a given day  |
| `by_barId_beverage_date`     | `[barId, beverageId, logDate]`           | Operating lookup — one bar book per beverage per day       |
| `by_userId_barId_bev_date`   | `[userId, barId, beverageId, logDate]`   | That waiter's row for one beverage on a day                |
| `by_beverageId`              | `[beverageId]`                           | Cross-user/bar history for a beverage                      |
| `by_propertyId`              | `[propertyId]`                           | Property-scoped lists                                      |
| `by_propertyId_logDate`      | `[propertyId, logDate]`                  | Hub health + dashboard Beverages today                           |
| `by_logDate`                 | `[logDate]`                              | Cron rollups by calendar day                               |

### 7. `storeTransactions`

Logs every movement of stock into or out of the central store. An `"issue"`
transaction is the authoritative source that drives `userStockLogs.newStockReceived`
updates for the matching calendar day.

> **v2.1 Changes:** `txnDateKey` (ISO 8601 string) is added alongside the
> existing `txnDate` (epoch ms) to enable efficient day-scoped lookups without
> timestamp arithmetic. Two new indexes support targeted lookups by user and bar
> per beverage per day.

| Field           | Convex Type                                              | Notes                                                       |
|-----------------|----------------------------------------------------------|-------------------------------------------------------------|
| `_id`           | `Id<"storeTransactions">`                                | Auto-generated by Convex                                    |
| `_creationTime` | `number`                                                 | Auto-generated by Convex                                    |
| `beverageId`    | `v.id("beverages")`                                      | Beverage being transacted                                   |
| `barId`         | `v.optional(v.id("bars"))`                               | Destination/source bar (`undefined` for supplier receive)   |
| `userId`        | `v.optional(v.id("users"))`                              | User who initiated the transaction                          |
| `txnType`       | `v.union(v.literal("receive"), v.literal("issue"), v.literal("count_adjust"))` | receive / issue / posted count variance |
| `qty`           | `v.number()`                                             | Bottles. For a crate receive this is `packQty × unitsPerPack`. For `count_adjust` this is the signed variance (counted − book). |
| `unitCost`      | `v.optional(v.number())`                                 | Landed cost per bottle on a receive. Older receipts stored a price already entered per bottle. |
| `totalCost`     | `v.optional(v.number())`                                 | Landed total: crates × price per crate, plus supply costs. Not set on issue or count adjust. |
| `packQty`       | `v.optional(v.number())`                                 | Crates on this receipt. Absent on issues, count adjustments, and receipts entered before crate costing. |
| `packPrice`     | `v.optional(v.number())`                                 | Price of one crate, before supply costs. |
| `unitsPerPack`  | `v.optional(v.number())`                                 | Bottles per crate, snapshotted on the receipt. |
| `supplyCosts`   | `v.optional(v.array(v.object({ label: v.string(), amount: v.number() })))` | Named costs of getting the drink in, such as transportation. Added once for the receipt, then included in the bottle cost. At most 8 lines. |
| `txnDate`       | `v.number()`                                             | Epoch ms timestamp — used for ordering                      |
| `txnDateKey`    | `v.string()`                                             | **[NEW]** ISO 8601 date e.g. `"2026-03-26"` — used for day-scoped `userStockLogs` lookups |
| `notes`         | `v.optional(v.string())`                                 | Optional reference or remarks                               |
| `stockRequestLineId` | `v.optional(v.id("stockRequestLines"))`             | Set when issue came from an approved request line           |
| `storeCountLineId`   | `v.optional(v.id("storeCountLines"))`               | Set when txn is a posted count adjust                       |

| `by_beverageId`           | `[beverageId]`                      | Movement history for a beverage                                 |
| `by_barId`                | `[barId]`                           | Transactions belonging to a bar                                 |
| `by_userId`               | `[userId]`                          | Collections made by a specific user                             |
| `by_txnType`              | `[txnType]`                         | Filter receives vs issues                                       |
| `by_beverageId_date`      | `[beverageId, txnDateKey]`          | Beverage movement on a specific calendar day (updated to string key) |

## Full Convex Schema (`convex/schema.ts`)

```typescript
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({

  bars: defineTable({
    name: v.string(),
    location: v.string(),
    barType: v.string(),
    isActive: v.boolean(),
  })
    .index("by_isActive", ["isActive"]),

  beverages: defineTable({
    name: v.string(),
    category: v.string(),
    unitOfMeasure: v.string(),
    unitsPerPack: v.optional(v.number()),
    unitPrice: v.number(),
    unitCost: v.optional(v.number()),
    manualUnitCost: v.optional(v.number()),
    reorderLevel: v.number(),
    isActive: v.boolean(),
  })
    .index("by_category", ["category"])
    .index("by_isActive", ["isActive"]),

  users: defineTable({
    externalId: v.string(),
    email: v.string(),
    name: v.string(),
    phone: v.optional(v.string()),
    isActive: v.boolean(),
    lastLoginAt: v.optional(v.number()),
    updatedAt: v.number(),
  })
    .index("by_externalId", ["externalId"])
    .index("by_email", ["email"])
    .index("by_isActive", ["isActive"]),

  shifts: defineTable({
    userId: v.id("users"),
    barId: v.id("bars"),
    shiftDate: v.string(),
    startTime: v.string(),
    endTime: v.optional(v.string()),
    isFinalized: v.boolean(),
  })
    .index("by_userId", ["userId"])
    .index("by_barId", ["barId"])
    .index("by_barId_date", ["barId", "shiftDate"])
    .index("by_userId_date", ["userId", "shiftDate"]),

  // Operating key: (barId, beverageId, logDate) where holder is "bar".
  // userId is the waiter or bartender. recordedByUserId is who entered the count.
  userStockLogs: defineTable({
    shiftId:          v.id("shifts"),
    userId:           v.id("users"),
    recordedByUserId: v.optional(v.id("users")),
    holder:           v.optional(v.literal("bar")),
    barId:            v.id("bars"),       // the bar that holds this stock
    beverageId:       v.id("beverages"),
    logDate:          v.string(),         // ISO 8601 e.g. "2026-03-26"
    openingStock:     v.number(),         // carried over from previous day's closingStock
    newStockReceived: v.number(),         // cumulative qty issued today via storeTransactions
    totalStock:       v.number(),         // openingStock + newStockReceived (persisted)
    closingStock:     v.number(),         // physical count at end of day
    salesQuantity:    v.number(),         // totalStock − closingStock (persisted)
    salesValue:       v.number(),         // salesQuantity × unitPrice (persisted)
    isFinalized:      v.boolean(),        // true after end-of-day reconciliation
    lastUpdatedAt:    v.number(),         // epoch ms of last mutation
  })
    .index("by_shiftId",               ["shiftId"])
    .index("by_userId_date",           ["userId", "logDate"])
    .index("by_barId_date",            ["barId", "logDate"])
    .index("by_userId_barId_date",     ["userId", "barId", "logDate"])
    .index("by_userId_barId_bev_date", ["userId", "barId", "beverageId", "logDate"])
    .index("by_barId_beverage_date",   ["barId", "beverageId", "logDate"])
    .index("by_beverageId",            ["beverageId"]),

  storeInventory: defineTable({
    beverageId: v.id("beverages"),
    qtyInStore: v.number(),
    reorderThreshold: v.number(),
    unitCost: v.optional(v.number()), // weighted average landed cost per bottle
    lastUpdated: v.number(),
  })
    .index("by_beverageId", ["beverageId"]),

  // v2.1: txnDateKey (ISO string) added for day-scoped userStockLogs lookups
  storeTransactions: defineTable({
    beverageId:  v.id("beverages"),
    barId:       v.optional(v.id("bars")),
    userId:      v.optional(v.id("users")),
    txnType:     v.union(v.literal("receive"), v.literal("issue"), v.literal("count_adjust")),
    qty:         v.number(), // bottles
    unitCost:    v.optional(v.number()), // landed cost per bottle
    totalCost:   v.optional(v.number()), // crates × crate price + supply costs
    packQty:     v.optional(v.number()),
    packPrice:   v.optional(v.number()),
    unitsPerPack: v.optional(v.number()),
    supplyCosts: v.optional(v.array(v.object({ label: v.string(), amount: v.number() }))),
    txnDate:     v.number(),       // epoch ms — for ordering
    txnDateKey:  v.string(),       // ISO 8601 e.g. "2026-03-26" — for day-scoped lookups
    notes:       v.optional(v.string()),
  })
    .index("by_beverageId",           ["beverageId"])
    .index("by_barId",                ["barId"])
    .index("by_userId",               ["userId"])
    .index("by_txnType",              ["txnType"])
    .index("by_beverageId_date",      ["beverageId", "txnDateKey"])
    .index("by_userId_beverage_date", ["userId", "beverageId", "txnDateKey"])
    .index("by_barId_beverage_date",  ["barId", "beverageId", "txnDateKey"]),

  reorderAlerts: defineTable({
    beverageId: v.id("beverages"),
    qtyAtAlert: v.number(),
    reorderLevel: v.number(),
    alertedAt: v.number(),
    status: v.union(
      v.literal("open"),
      v.literal("acknowledged"),
      v.literal("resolved")
    ),
  })
    .index("by_beverageId", ["beverageId"])
    .index("by_status", ["status"])
    .index("by_beverageId_status", ["beverageId", "status"]),

  salesSummaries: defineTable({
    barId: v.id("bars"),
    userId: v.optional(v.id("users")),
    beverageId: v.id("beverages"),
    periodType: v.union(
      v.literal("daily"),
      v.literal("weekly"),
      v.literal("monthly"),
      v.literal("yearly")
    ),
    periodKey: v.string(),
    year: v.number(),
    month: v.optional(v.number()),
    weekNumber: v.optional(v.number()),
    totalQtySold: v.number(),
    totalRevenue: v.number(),
  })
    .index("by_barId_period",           ["barId", "periodType", "periodKey"])
    .index("by_userId_period",          ["userId", "periodType", "periodKey"])
    .index("by_beverageId_period",      ["beverageId", "periodType", "periodKey"])
    .index("by_barId_beverage_period",  ["barId", "beverageId", "periodType", "periodKey"])
    .index("by_year_periodType",        ["year", "periodType"]),

});
```
